# `tools/grain-plates` — offline synthesis of the film-grain plates

Offline half of stage **G2** of `FilmGrainSpec.md`. Produces the shipped asset described in
spec §3.3: `Assets/Grain/<sizeClass>.dds`, a Texture2DArray of 8 independent 512² plates with a
full mip chain, plus a JSON sidecar carrying every number the shader and the acceptance tests
need. Pure Python, uv, PEP 723 — **no engine code and no engine dependency**; this writes assets
and nothing else.

Design context: `scene-notes/grain/PROPOSALS.md` P1 (plates) and P3 (the Boolean model, used here
as the *offline generator*, option (iii) of P3's runtime discussion), §8 items 1 and 3;
`scene-notes/grain/01-requirements.md` R3.

## Requirements

Python is managed by **uv** only — no global installs. `make_plates.py` carries PEP 723 inline
metadata, so there is nothing to install by hand: `uv run` resolves `numpy` on the first call.
`matplotlib` is needed *only* for the `--preview` spectrum plot and is therefore not in the
script's dependency list — pass it with `uv run --with matplotlib`. Pillow is never needed: the
PNG writer is 12 lines of `zlib` in the script, and so is the DDS writer.

## Usage

```
uv run make_plates.py --out out                                   # all four classes
uv run --with matplotlib make_plates.py --out out --preview       # + slice0 / spectrum PNGs
uv run make_plates.py --out out --classes medium --seed 4242
uv run make_plates.py --out out --classes medium --target-spectrum
uv run make_plates.py --verify out/medium.dds                     # exit 0 = good, 1 = mismatch
```

`out/` is scratch and git-ignored (`.gitignore` in this directory). The shipped plates are
copied into the engine plugin's asset tree by hand, like the baked LUTs of `tools/ocio-bake`.

Options: `--seed` (master seed, default `20260905`; the whole run is deterministic from it),
`--slices` (8), `--plate-px` (512, must be a power of two), `--supersample` (8),
`--classes` (comma-separated).

## The model

One layer of one plate is a realisation of the **Boolean grain model** — Newson, Delon &
Galerne, *A Stochastic Film Grain Model for Resolution-Independent Rendering* (CGF 2017), and
the IPOL article *Realistic Film Grain Rendering* (2017) — evaluated offline at true micrometre
scale:

* grain centres are a **periodic Poisson process on the torus** with intensity
  `λ = −ln(1 − u) / (π·E[r²])`, `u = 0.5`, so the expected coverage is exactly `u`;
* radii are **log-normal** with mean `r̄_layer` and `σ_r = 0.25·r̄_layer`
  (so `E[r²] = r̄² + σ_r²`);
* the plate value is the **area fraction** of the texel covered by the union of discs, estimated
  by 8×8 supersampling; each disc is rasterised inside its own bounding box, and the box indices
  are taken modulo the plate size — that modulo is the whole of the periodicity.

Because the process is periodic there is **no edge blending anywhere**. Cross-fading tiles is
the usual shortcut and it changes the spectrum (PROPOSALS P1); a torus does not.

Three layers per plate with per-layer `r̄` ratios **B 1.25 / G 0.8 / R 1.0** of the class `r̄`
(spec §3.3), independent seeds, plus a fourth independent layer in alpha (see Decisions).

Plate texel size is `r̄ / 2` µm, so a 512² plate covers `256·r̄` µm of negative.

### Normalisation and the 8-bit encoding

Per layer, per slice: mean removed, scaled to unit variance, then

```
byte = 127.5 + scale · n        scale = 32.0        n = (byte − 127.5) / scale
```

`scale` is in the sidecar (`normalisation.scale`) so the shader recovers unit variance exactly.
32.0 gives 3.98 σ of headroom; measured peak on the shipped plates is **1.161–1.163 σ** and
`normalisation.clipped_texels` is **0** for every class — the Boolean coverage field is bounded
in [0, 1], so it cannot produce Gaussian-style outliers.

### Mips = the footprint integration

The full mip chain is generated by 2×2 box averaging of the **periodic** float field, per slice,
*before* quantisation (so mip *n* is not a re-quantisation of mip *n−1*). Every level is a power
of two, so the 2×2 boxes tile the plate exactly and no texel of any level ever reads outside the
plate — the wrap is satisfied by construction, not by a border case.

This averaging is exactly the footprint integration the shader relies on (spec §3.1, R3.2): the
shader samples at `LOD = log2(fp_um / plateTexel_um)` and gets the variance of the coverage of a
texel that many times larger — the physically right amount of sub-pixel grain averaging, for
free, from trilinear filtering. The per-mip variance is recorded in the sidecar so the runtime
side can be checked against it.

### Spectrum, and why the filter is √S(f)

The default output is the **raw Boolean plate**. Its spectrum is not white — it is the spectrum
of a Boolean model of discs of that size, which is the physical one (R3.3), so there is nothing
to shape.

`--target-spectrum` exists for the case where a *target* spectrum is known from elsewhere (a
scan, or the Zhang et al. 2023 statistics — PROPOSALS §8 item 1). In that mode a white Gaussian
field is reshaped by a filter fitted from the Boolean plate. The filter **magnitude** must be
`√S(f)`, **not** `S(f)` (PROPOSALS §8 item 3): filtering a field with `H` multiplies its *power*
spectrum by `|H|²`, so obtaining power `S` from a unit-power white field needs `|H| = √S`. Using
`S(f)` as the magnitude would square the spectrum, doubling the roll-off slope in log-log and
producing grain that looks far softer and more clumped than the model it was fitted to. This is
the single easiest mistake in the whole tool, which is why it has its own function with its own
docstring (`shape_white_by_sqrt_s`).

Measured: reshaping by `√S(f)` reproduces the Boolean plate's radial spectrum to a **median
relative error of 3.3–3.9 %** per layer (90th percentile 10–11 %), which is realisation noise,
not bias.

## Output

Per class:

| File | What |
|---|---|
| `<class>.dds` | DX10-header DDS, `DXGI_FORMAT_R8G8B8A8_UNORM`, `D3D10_RESOURCE_DIMENSION_TEXTURE2D`, `arraySize` 8, 512², 10 mips, 11 184 948 bytes. Data is slice-major (every mip of slice 0, then slice 1, …). |
| `<class>.json` | sidecar: `r̄` per layer, `texel_um`, `plate_extent_mm`, Poisson/log-normal parameters, grain counts, per-slice/per-mip mean and variance, normalisation scale, seed, tool version, sha256 and size of the DDS |
| `<class>.spectrum.json` | radial power spectrum per layer (slice 0), cycles per plate |
| `<class>_slice0.png`, `<class>_spectrum.png` | `--preview` only |

## Verification (`--verify`)

`uv run make_plates.py --verify out/<class>.dds` reloads the DDS *through its own parser* and
checks, in this order:

1. DDS magic, `DDS_HEADER` size, DX10 FourCC, DXGI format, resource dimension;
2. **sha256 and byte size** against the sidecar — bit-exact integrity, because the statistical
   checks below are deliberately tolerant and would not notice a handful of flipped bytes
   (verified: flipping one byte of the pixel data is caught by the hash and by nothing else);
3. width, height, array size, mip count, and that the file ends exactly at the end of the mip
   chain (no trailing bytes);
4. every mip of every slice is the right size, and its **mean and variance re-measured from the
   file** match the sidecar (`atol` 1e-4 on the mean, `rtol` 1e-5 on the variance);
5. mip 0 mean is within 0.5 LSB of 127.5, and the mean mip-0 variance is 1.0 ± 0.05.

Exit code 0 = all good, 1 = mismatch, 2 = usage error.

## Measured numbers (run of 2026-09-05, seed 20260905, numpy 2.x, 8×8 supersampling)

### Plate extent

| Class | `r̄` (µm) | texel (µm) | plate extent (mm) | grains / slice (R / G / B) |
|---|---|---|---|---|
| `fine` | 3 | 1.5 | **0.768** | ≈ 13 570 / 21 270 / 8 730 |
| `medium` | 6 | 3.0 | **1.536** | ≈ 13 640 / 21 350 / 8 730 |
| `coarse` | 12 | 6.0 | **3.072** | ≈ 13 640 / 21 260 / 8 730 |
| `xcoarse` | 24 | 12.0 | **6.144** | ≈ 13 550 / 21 380 / 8 630 |

Measured coverage is 0.490–0.510 per layer per slice against the target 0.500.

**The four classes are statistically the same plate at four scales.** Because the texel is
defined as `r̄ / 2`, the grain radius in *texel* units is 2.0 / 1.6 / 2.5 for R / G / B in every
class; only `texel_um` and hence the mm extent differ. That is a property of the spec, not a
bug, and it is worth knowing: the classes are not four different grain *structures*, they are
one structure sampled at four negative scales, and only the independent seeds keep the four
files from being byte-identical. If we ever want a genuinely different structure per class
(fast stock = wider `σ_r`, more clumping), `σ_r/r̄` or the coverage has to become per-class.

Two sanity checks pass by inspection: the **B layer (largest grain) keeps the most variance at
every level** and the G layer the least, which is the correct ordering — larger grains survive

below mip 6 is under 1/255 of full scale, i.e. the plate is correctly "empty" once a screen
pixel integrates thousands of grains.

### Spectrum knee (half-power point of the radially averaged S(f), mean over 8 slices)

| Class | R (cyc/mm) | G | B | `1/(2·r̄)` |
|---|---|---|---|---|
| `fine` | 74.2 | 89.8 | 59.9 | 166.7 |
| `medium` | 37.1 | 44.9 | 31.2 | 83.3 |
| `coarse` | 18.6 | 22.1 | 15.6 | 41.7 |
| `xcoarse` | 9.4 | 10.9 | 7.8 | 20.8 |

The knee scales exactly as `1/r̄` across the four classes (ratio to `1/(2·r̄)` is 0.445 ± 0.001
everywhere) and orders G > R > B, i.e. by inverse grain size. That is R3.3 satisfied by the
model rather than imposed by a filter.

### Wall-clock

* Full run, four classes, 8 slices, 512², 8×8 supersampling, `--preview`:
  **51 s** (12.1–12.2 s per class), on the dev machine, single-threaded numpy.
* `--verify` on all four: **1.4 s** total.
* Total output: 4 × 11 184 948 bytes = **42.7 MiB** of DDS (uncompressed RGBA8 with mips).

Well inside "minutes, not hours". The cost is dominated by the ~44 000 disc rasterisations per
slice, each a bounding-box numpy op; there is no per-pixel Python loop anywhere.

## Decisions

Things the spec left open, decided here.

1. **The alpha channel carries a fourth, independent monochrome layer** (`r̄` ratio 1.0, its own
   seed), rather than being padded to 255. The brief says "three layers per plate", and R/G/B are
   those three; but the format is R8G8B8A8 and spec §3 needs a *fourth independent field*
   `n_mono` for the channel-correlation term `n_c = √ρ·n_mono + √(1−ρ)·n_c,indep`. Leaving alpha
   constant would waste a quarter of a 42 MiB asset and force the shader to synthesise `n_mono`
   some other way, at a different spectrum from the layers it is being mixed with — which would
   be audible as a colour-dependent grain size as ρ moves. Cost: zero (the texel is 4 bytes
   either way). If the shader ends up not wanting it, ignore the channel.

2. **Supersampling default is 8×8, not the 4×4 of the brief.** PROPOSALS §8 item 4 says
   under-integrated estimator noise must never pass as grain, and an `n×n` estimate of a texel's
   coverage carries a binomial estimator variance of `p(1−p)/n²` on top of the true variance.
   Measured on one `medium` slice, R layer, at 4 / 8 / 16 samples per axis:

   | mip | ss=4 | ss=8 | ss=16 |
   |---|---|---|---|
   | 1 | 0.77409 | 0.78588 | 0.78585 |
   | 2 | 0.46164 | 0.46454 | 0.46497 |
   | 3 | 0.17947 | 0.18043 | 0.18083 |
   | 4 | 0.05614 | 0.05628 | 0.05650 |

   4×4 is low by 1.5 % at mip 1 and under 0.6 % below that; 8×8 and 16×16 agree to 0.2 %. So the
   estimator is essentially converged at 8×8, the residual white estimator noise at mip 0 is
   halved relative to 4×4, and the cost is 12.1 s per class instead of 9. `--supersample 4`
   reproduces the brief's figure exactly if it is ever wanted for comparison.

3. **Quantisation scale is a fixed 32.0, not fitted per class.** A per-class fitted scale would
   buy about 1.5 bits (measured peak is 1.163 σ, so a fitted scale could be ~109) but makes the
   plates non-interchangeable and the shader's constant class-dependent. 32.0 is a power of two,
   is safe for any future plate whose peak stays under 3.98 σ, and is recorded in the sidecar
   anyway. Zero clipped texels across all four classes confirms the headroom.

4. **Mips are averaged in float and quantised once per level**, not produced by averaging the
   8-bit mip above. Averaging bytes would accumulate rounding, and the deep mips (variance
   0.0003) would be destroyed by it.

5. **Mip 0 variance is not exactly 1.0** — measured 0.977 to 1.012. It is 1.0 by construction
   before quantisation; rounding to 8 bits moves it by up to ~1.5 % because the coverage field is
   nearly binary at texel scale (a texel is `r̄/2` across, a grain is `r̄` in radius, so most
   texels are fully in or fully out) and therefore takes few distinct values, so the rounding
   error correlates with the value instead of averaging out. This is why the sidecar records the
   *measured* variance per slice and per mip: the runtime should trust those numbers, not the
   nominal 1.0. `--verify` accepts 1.0 ± 0.05 for the global check and demands an exact match
   against the sidecar for every individual mip.

6. **A sha256 of the DDS is in the sidecar and checked first by `--verify`.** The statistical
   checks are tolerant by design; without a hash, `--verify` passed a file with a corrupted pixel
   byte. Tested both ways.

7. **`--target-spectrum` fits its target from the Boolean plate of the same class**, since that
   is the only target we have today. When scan-derived or Zhang-style statistics arrive, the
   target should come from a file; the reshaping function itself does not change.

8. **The DDS writer sets `DDSD_PITCH` with the top-level pitch** and `DDSCAPS_COMPLEX |
   DDSCAPS_MIPMAP | DDSCAPS_TEXTURE`, `miscFlag` 0 (not a cube map), `miscFlags2` 0
   (`DDS_ALPHA_MODE_UNKNOWN`). Array data is slice-major, which is what D3D11's own
   `DDSTextureLoader` expects; `dds_read` in the same file is the round-trip proof.

9. **No BC compression.** Spec §3.3 allows "BC-free RGB8"; block compression on zero-mean noise
   is the worst case for BC1/BC7 (every 4×4 block is uncorrelated) and would destroy exactly the
   high-frequency structure the plate exists for. 42.7 MiB for the four classes, or 10.7 MiB for
   the one class a given preset uses, is the right trade.

## Not done here

The runtime half of G2 (the shader's plate sampling, the 64-variant tile hash, LOD selection) is
a separate stage. This tool only guarantees that the asset it emits is periodic, zero-mean,
unit-variance, correctly mip-filtered and measured.
