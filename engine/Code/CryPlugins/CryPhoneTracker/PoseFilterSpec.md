# PoseFilter 規格 — CryPhoneTracker 進階姿態濾波管線目標：手持虛擬攝影機的「電影感」。三個可感知的驗收目標，優先序由高到低：1. **構圖停頓時畫面完全靜止**（如上腳架，不是「幾乎不動」）2. **運鏡跟手**（1 m/s 移動時濾波額外延遲 < 10ms）3. **120fps 下絲滑**（30Hz 封包不得出現階梯感或因網路抖動的速度波動）技術取捨一律以感知效果為準。---## 0. 範圍與位置- 只改引擎側：`Code/CryPlugins/CryPhoneTracker/Module/`。  **不得**修改 Android app、封包協定（`PhoneTrackerProtocol.h` 的 wire format）、CinematicCamera。- 新增自包含檔案 `Module/PoseFilter.h`（header-only struct，僅依賴 CryMath / CryCore 基本型別，  不碰 gEnv），單元可測。`PhoneTrackerComponent` 只做接線。- 濾波運作於 **tracker 空間**（ARCore 轉 Cry 軸後的原始 pose，公尺制），  在既有的 origin/yaw/scale/offset 世界映射**之前**。這樣所有閾值都是物理單位，  不受 `Metres To Units` / `Yaw Offset` 影響。- 無動態配置：所有狀態為固定大小成員（環形緩衝 16 筆）。全部在主執行緒。## 1. Stage A — 時基重建（clock mapping + jitter 吸收）封包自帶 `frameNs`（手機 ARCore 幀時間戳，單調）。以它為樣本時間軸，把網路到達抖動隔離在時間映射層：- 維護 `offsetNs = EMA(engineNowNs − frameNs)`，EMA α = 0.05。  首個樣本直接初始化。每樣本對估計值的修正量 clamp 在 ±2ms（緩慢吸收時鐘漂移）。- 若瞬時 offset 與估計值差 > 200ms → 硬重置（手機時鐘跳變 / session 重啟）。- 樣本的引擎時間 = `frameNs + offsetNs`。- 以 seq 與 frameNs 拒收亂序/過期樣本（frameNs ≤ 上一筆者丟棄）。- 封包間隔估計：`intervalNs = EMA(ΔframeNs)`，α = 0.1，clamp [4ms, 100ms]，初值 33ms。## 2. Stage B — One Euro（封包率執行，每收到一筆有效 pose 跑一次）採樣間隔 `Te = ΔframeNs`（秒），clamp [1/240, 0.2]。通用低通：`alpha(fc) = 1 / (1 + tau/Te)`，`tau = 1/(2π·fc)`。### 位置（Vec3）```v_raw   = (x − x_prev) / Te                  // 每軸v_hat   = v_hat + alpha(dCutoff)·(v_raw − v_hat)   // dCutoff = 1.0 Hz 固定speed   = |v_hat|                            // 向量長，三軸共用 cutoff（避免各軸糊化不一致）fc      = posMinCutoff + posBeta · speedx_hat   = x_hat + alpha(fc)·(x − x_hat)      // 每軸，同一個 fc```### 旋轉（Quat）```q_delta = q_prev^-1 · q_new                  // 先確保最短弧：dot<0 則 q_new 取負angle   = 2·acos(clamp(q_delta.w, -1, 1))    // radw_raw   = angle / Te                         // 角速率 rad/s（純量即可）w_hat   = w_hat + alpha(dCutoff)·(w_raw − w_hat)fc      = rotMinCutoff + rotBeta · w_hatq_hat   = Slerp(q_hat, q_new, alpha(fc))，之後 Normalize```輸出（`t, x_hat, v_hat, q_hat, w_hat`）推入環形緩衝（16 筆）。### 預設參數（反映到 Schematyc 屬性）| 屬性 | 預設 | 範圍 | 說明 ||---|---|---|---|| posMinCutoff | 1.0 Hz | 0.1–10 | 靜態位置抖動抑制強度（越低越穩） || posBeta | 0.5 (per m/s) | 0–5 | 高速跟隨性 || rotMinCutoff | 1.2 Hz | 0.1–10 | 靜態旋轉抖動抑制 || rotBeta | 0.1 (per rad/s) | 0–5 | 旋轉跟隨性 |dCutoff 固定 1.0 Hz，不暴露。## 3. Stage C — 虛擬腳架（Tripod / steady mode）目標：構圖停頓 → 畫面**完全**鎖死；起步 → 無黏滯感地平滑接回。含遲滯避免顫振。狀態機（作用於 Stage B' 重採樣後的 tracker 空間 pose）：- **MOVING → ARMING**：`|v_hat| < enterSpeed (0.015 m/s)` 且 `w_hat < enterAngular (0.8 deg/s)`  開始計時；持續 `holdTime (0.25 s)` → 進入 **STEADY**，錨定  `anchor = 當前輸出 pose`。任一超標即重置計時回 MOVING。- **STEADY**：輸出 = anchor 以極低通緩慢追隨 live pose（固定 fc = 0.1 Hz，位置 EMA + 旋轉 Slerp），  吸收 ARCore 慢漂移但視覺上不可察覺。- **STEADY → MOVING（退出條件，任一）**：  - `|live_pos − anchor_pos| > exitPosition (0.01 m)`  - `angle(live_q, anchor_q) > exitAngle (0.5 deg)`  - `|v_hat| > exitSpeed (0.05 m/s)`  退出時**不得跳變**：啟動 `blendTime (0.15 s)` 的 smoothstep 混合，從 anchor 過渡到 live。  混合期間若再次滿足進入條件，允許直接以當前輸出重新錨定。暴露屬性：`tripodEnabled`（預設 on）、enterSpeed、holdTime、exitPosition、blendTime。enterAngular / exitAngle / exitSpeed 用上表常數即可，不必全部暴露（保持面板簡潔）。## 4. Stage B' — 定延遲重採樣（渲染率執行，每幀）- 查詢時間 `t_query = engineNowNs − interpDelayFactor × intervalNs`，  `interpDelayFactor` 屬性，預設 1.5（範圍 1.0–4.0）。- 在環形緩衝找包夾 `t_query` 的兩筆：  - **位置**：cubic Hermite（端點用各自的 `v_hat` 當切線）。  - **旋轉**：Slerp（B 級已濾過，squad 不必要）。- `t_query` 超出最新樣本（斷流）：  - 允許外插至多 `maxExtrapolationMs`（屬性，預設 0 = 關閉，範圍 0–80），    使用最新 `v_hat` 並隨超出時間線性衰減至 0。  - 超過外插上限 → 凍結在最後 pose。既有 `Signal Timeout` 邏輯不變。- 緩衝不足兩筆 → 直接輸出最新樣本。## 5. 接線與相容性- `ReceivePackets()`：解析出有效 pose 後（`ePoseFlag_Valid`），餵 `PoseFilter::Push(frameNs, pos, quat)`。  origin/epoch 邏輯不變，但注意：**origin 捕捉使用濾波後的當前輸出**（避免抖動被凍進原點）。- `ApplyPose(frameTime)`：改為  `filter.Sample(engineNowNs) → tripod → 既有世界映射（origin/yaw/scale/offset）→ 寫 entity`。  `m_applyPosition / m_applyRotation` 語義不變。- **既有 `Smoothing Half Life` 保留但預設改 0**，並在描述註明已被 Pose Filter 取代  （設 >0 時作為最後一段額外平滑，串在管線之後，行為同現狀）。- 新增總開關屬性 `Filter Mode`（enum：`Off` / `OneEuro` / `Cinematic`，預設 `Cinematic`）。  `Off` = 完全跳過管線（等同現狀）；`OneEuro` = 只有 A+B+B'；`Cinematic` = 全部。- **重置規則**（全部觸發 `PoseFilter::Reset()`，以下一筆樣本重新初始化，不得出現暫態擺動）：  socket 開啟、recenter / originEpoch 變更、`ePoseFlag_SessionResumed`、  訊號中斷超過 Signal Timeout 後恢復。- Debug Draw 增加一行：目前模式（MOVING/ARMING/STEADY+blend）、`|v_hat|`、`w_hat`(deg/s)、  有效 fc、緩衝深度、目前重採樣延遲 ms。## 6. 非目標（明確不做）- 不做鏡頭值（focal/aperture/focus）濾波。- 不做神經網路 / Minilag 類回溯補償。- 不改協定、不改 Android、不動 CinematicCamera。## 7. 驗收清單1. 手機平放桌面 30 秒：STEADY 進入後 entity transform 完全不變（逐位元），無顫振進出。2. 慢速起步：離開 STEADY 無可見跳變或黏滯突跳（blend 生效）。3. 快甩：Cinematic 與 Off 目測延遲差異不可察（< 1 幀 @60fps 量級）。4. 模擬 200ms 封包中斷再恢復：無位置跳變（外插關閉時凍結、恢復後平滑接回）。5. Recenter：與現狀相同，不瞬移，且濾波器無暫態。6. `Filter Mode = Off` 的行為與現版本逐幀一致（回歸保證）。7. 三個 config（Profile 必須；Debug/Release 至少編譯通過）建置成功，無新警告（/W3 /WX 環境）。## 8. 建置與部署（給實作者）- 一律用引擎內附 CMake：`Tools\CMake\Win32\bin\cmake.exe`（系統 CMake 4.x 會在 CMP0040 失敗）。- 建置：`cmake --build solutions_cmake\win64 --config Profile --target CryPhoneTracker`- 新檔 `PoseFilter.h` 記得加入 `Module/CMakeLists.txt` 的 `add_sources`。- 部署（若檔案被佔用則回報，不要強砍程序）：  `bin\win_x64\CryPhoneTracker.dll` → `S:\Crytek\crytek\cryengine-57-lts\5.7.1\bin\win_x64\`  與 `S:\Crytek\crytek\cryengine-gamesdk-sample-project2\5.7.1\bin\win_x64\`（連同 .pdb）。- 不 commit。程式碼與註釋使用英文，風格對齊現有檔案（tab 縮排、Cry 命名慣例）。
