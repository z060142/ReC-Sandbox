# Hybrid DOF（Sprite Bokeh 2.0）規格演進目標:把互斥的 mode 0（全潑濺）/ mode 1（gather）合體為業界現代做法——**gather 當底、潑濺只給亮點**（UE Diaphragm DOF / Frostbite 同族)。一石四鳥:模式互斥消失、潑濺量化閃爍的舞台縮小百倍、fillrate 有界、形狀貼圖與多邊形交集全數保留。前提:本規格動工前,v1(復刻版,mode 0=全潑濺)已 commit 留存,可隨時回溯對照。## 1. 新語意- `r_DepthOfFieldMode 1`(預設):純 gather,行為與現在**逐位元相同**。- `r_DepthOfFieldMode 0`:**Hybrid**——先跑完整 gather(與 mode 1 同一條路),  再疊亮點潑濺層。舊的全潑濺路徑退役(git 歷史留存,不留執行期開關)。- Plugin 的 `Use Sprite Bokeh` 屬性語意不變(驅動 cvar),文檔另更新。## 2. Hybrid 管線1. **Gather 先行**:mode 0 也執行既有 gather 全流程(含多邊形 kernel、   Focus Falloff、blur amount)。輸出與 mode 1 相同的模糊場景。2. **亮點篩選(在既有 sprite VS 內做,不引入 compute)**:   每 quad 取樣來源像素後,以**場景 HDR 亮度的軟膝閾值**決定去留:   ```   excess = max(0, luminance - threshold)        // soft knee 比照 streaks 的作法   if (excess 很小 || fDepthBlur 很小) → quad 歸零丟棄(現有 kill 路徑)   splat 顏色 = 色相保留 × excess 部分的能量     // 只潑「gather 表現不了的超出能量」   ```   只潑 excess 是能量雙算的解法:gather 已把基礎能量糊開,潑濺補的是高光在   gather 下被壓扁的那部分。閾值參數 `Dof_User_HighlightThreshold`   (post param,預設 2.0,場景 HDR 值域,plugin 端暫不暴露屬性——等實測後決定)。3. **合成順序改變**:潑濺層 normalize 後以加法(或 premultiplied over)疊在   **gather 結果**之上——不再是「潑濺 vs 銳利場景」的取代式合成。   v1 的 normalize pass 邏輯對應改寫。4. 形狀貼圖、多邊形交集、blade rotation(上一輪剛統一)在潑濺 PS 內原樣保留。## 3. 穩定性- 軟膝要夠寬(threshold 的 ±50%)以抑制亮點在閾值邊緣的 popping;  變焦/光圈快速變化下不得出現整窗閃爍(上一輪修的 bDofEnabled 遲滯照舊有效,  hybrid 下 vFocus.w 的語意不變)。- 半解析度來源的量化閃爍:潑濺數量級縮小後應大幅緩解;若殘留,  來源取樣改 2x2 平均(預濾波)——做成程式常數,不用暴露。## 4. 驗收1. mode 1 逐位元不變(gather 段 diff 為空)。2. mode 0:全畫面有 gather 模糊(v1 沒有的!) + 失焦亮點上有形狀潑濺   (貼圖形狀/多邊形交集/rotation 皆作用)。3. 亮點潑濺與 gather 光斑同位置、尺寸一致(CoC 同源),無「雙重光斑」錯位。4. 一般場景(無極亮點)mode 0 ≈ mode 1 畫面,潑濺量 ~0。5. 快速拉光圈/變焦:無整窗條紋、無亮點 popping 群舞。6. 效能:mode 0 在 1080p 高光場景 < gather + 1ms(潑濺已稀疏化)。7. 既有一切(星芒、gather 多邊形、診斷 cvar)不回歸。## 5. 建置部署約束同前輪:內附 CMake、Profile 零警告、部署至慣例位置(備份不可動、鎖檔回報)、loose `DepthOfField.cfx` 隨部署、不 commit(由主線驗收後統一收)。
