# Sprite Bokeh 復活 + 形狀遮罩交集 規格目標兩層:1. **復活** CE3/Cinebox 世代的 sprite 散景路徑——shader 技術 `DofBokehRef` 完整存活於   `Engine/Shaders/HWScripts/CryFX/DepthOfField.cfx`(36–236 行),但 C++ 宿主   `CMotionBlur::Execute()`(`XRenderD3D9/PostProcessMotionBlur.cpp` 330–401 行)使用舊管線   API(`gRenDev->m_RP`),在 5.7 的新 graphics pipeline 中不可達。把那段繪製移植成新管線的 pass。2. **超越原設計**:形狀遮罩貼圖 + 與光圈葉片多邊形的**物理交集**(有效孔徑 = 遮罩 ∩ 葉片   多邊形,「誰小誰贏」)。原 Cinebox 只有程序式圓盤+ring;交集行為是新的。## 1. 移植(先讓原功能跑起來)- 落點:`XRenderD3D9/GraphicsPipeline/DepthOfField.cpp` 的 `CDepthOfFieldStage`。  `Execute()` 開頭分流:`CRenderer::CV_r_DofMode == 0` → `ExecuteSpriteBokeh()` 並 return;  否則走既有 gather 路徑(**gather 路徑一個位元組都不准變**,含多邊形 kernel、  `r_DepthOfFieldBokehShapeStrength`、`r_DepthOfFieldBokehQuality` 診斷)。cvar 已註冊  (`r_DepthOfFieldMode`,預設 1),語意即原本的 0=sprite/1=gather。- 逐行研讀 `PostProcessMotionBlur.cpp` 330–401 的舊實作再移植:quad 數  (`nWidth*nHeight*3*2`,一像素一 quad、6 頂點、無 vertex buffer,VS 用 `SV_VertexID`  自算位置)、`fBokehNormFactor` 正規化、technique `"DofBokehRef"`、輸入貼圖  (scene target / scene depth / dither)、加法混合與繪製狀態。新管線用  `CPrimitiveRenderPass` + `CRenderPrimitive`(procedural、無 VB、自訂頂點數)——  參考引擎中其他 procedural 多頂點 draw 的寫法。- 常數 `vDofParamsFocus0/1` 與 gather 共用同一來源(`CDepthOfField::GetParams()`  已提供),shader 端已在用,不用改語意。- 解析度/目標:依舊實作(半解析度 scene target 累積後合成;細節以舊碼為準,  不確定處以「能在畫面上正確出現 sprite 光斑」為準,並在報告中記錄決定)。## 2. 形狀遮罩 + 交集(shader 修改,`DofBokehRefPS` 一帶)- 新貼圖槽:`Dof_User_BokehShapeTex`(post param,`AddParamTex`,參考既有  `MotionBlur_MaskTexName` 的模式;`CDepthOfField` 加 `m_pBokehShapeTex`)。  Stage 綁定該貼圖;未設定時走原本的程序式圓盤+ring(行為不變)。- PS 中 quad 區域性 UV 已可推得(quad 展開的插值座標);  `shape = 貼圖有效 ? tex.Sample(quadUV).r : 原程序式形狀`。- **交集項**(物理核心,一個乘法):把 `NGon_Rad(theta, n) = cos(PI/n)/cos(theta − (2PI/n)·floor((n·theta+PI)/(2PI)))`  移植進 shader(C++ 版在 `GraphicsPipeline/DepthOfField.cpp` 頂部),以軟邊裁切:  ```hlsl  // r, theta: quad 區域極座標(r=1 為 quad 邊界內切圓)  float polyR = NGon_Rad(theta, blades);  float polyMask = saturate((polyR - r * blend) / edgeSoft + (1 - blend) * BIG);  shape *= polyMask;  ```  `blend` 用與 gather kernel 相同的窗口:f/1.2 → 0(全圓,不裁)、f/2.8 → 1(完整多邊形),  乘上 `r_DepthOfFieldBokehShapeStrength` 的可讀性語意可省略(sprite 光斑本來就大,物理值即可讀)。  葉片數與 f 值經既有 `Dof_User_ApertureBlades` / `Dof_User_FNumber` post params 傳入  (已存在,gather 在用),shader 端加兩個常數傳遞即可。- 湧現行為驗收:全開=純遮罩形狀;收光圈=多邊形逐漸啃進遮罩;無遮罩=多邊形 sprite 散景。## 3. Plugin 端(CinematicCamera)- Lens 抽屜新增:  - `Use Sprite Bokeh`(bool,預設 false)——以 MB/LensCharacter 相同的 cvar 存還原模式驅動    `r_DepthOfFieldMode`(true→0,false→還原)。id 需查現有 4CC 不衝突。  - `Bokeh Shape Texture`(`Schematyc::TextureFileName` 資源選擇器,預設空)——經    `SetPostEffectParamString` 送 `Dof_User_BokehShapeTex`。- 寫入時機與其他 DOF 參數相同(`ApplyDOF`);還原鏈全覆蓋(Deactivate / OnShutDown /  RESET / 換相機搶手),照 `ApplyMotionBlur`/`RestoreMotionBlur` 的模式。## 4. 測試素材引擎自帶 flare/glow 貼圖裡找一張非圓形的(`engine`/`EngineAssets` 的 textures 裡搜star/flare 形狀)當冒煙測試素材,把路徑寫在報告裡;自訂愛心等留給使用者自備。## 5. 硬性約束- 只用內附 CMake(`Tools\CMake\Win32\bin\cmake.exe`),target `CryRenderD3D11` 與  `CinematicCamera`,Profile 零錯誤零警告(/W3 /WX)。- gather DOF、多邊形 kernel、星芒、既有全部功能不得回歸;`r_DepthOfFieldMode` 預設維持 1。- shader 為 loose file 部署(引擎執行期編譯);部署清單:  `CryRenderD3D11.dll/.pdb` → `S:\Crytek\crytek\cryengine-57-lts\5.7.1\bin\win_x64\`  (`.official-backup` 不得動);`CinematicCamera.dll/.pdb` → 該處與  `S:\Crytek\crytek\cryengine-gamesdk-sample-project2\5.7.1\bin\win_x64\`;  `DepthOfField.cfx` → `S:\Crytek\crytek\cryengine-57-lts\5.7.1\engine\shaders\HWscripts\CryFX\`  (原始無 loose 檔則直接放,若已存在同名 loose 檔先備份)。檔案被鎖時回報,不殺程序。- 不 commit。程式碼註釋英文,風格對齊各檔案現況。## 6. 驗收清單(runtime 由使用者執行)1. `r_DepthOfFieldMode 1`(預設):一切與現在完全相同。2. `r_DepthOfFieldMode 0` + DOF 開 + 大光圈:sprite 光斑出現(程序式圓盤+ring,   即 Cinebox 原味 soap-bubble 散景)。3. 指定 shape 貼圖:全開時光斑呈貼圖形狀。4. 收光圈 f/1.2→f/2.8→f/5.6:多邊形逐漸啃進貼圖形狀(交集),繼續收則趨近純多邊形。5. `Use Sprite Bokeh` 屬性開關等效於 cvar,還原鏈正確。6. 效能:1080p sprite 模式 < 3ms(舊實作的正常水位)。
