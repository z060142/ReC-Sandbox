# CinematicCameraA physically based camera component driven by real lens parameters (Sandbox category:**Cameras / Cinematic Camera**):- **FOV** from focal length + sensor size, written into the sibling `CCameraComponent` the  component creates automatically (so the entity shows up in Sandbox's Camera Entity menu and  the editor viewport previews it with the correct frustum).- **DOF** from aperture + focus distance through the thin-lens equations, written to the  `Dof_User_*` post effect params.- **Exposure** written to `E3DPARAM_HDR_EYEADAPTATION_PARAMS` from the plugin's  `UpdateBeforeFinalizeCamera()` hook (after the Time of Day update, so TOD cannot overwrite  it in the same frame).- Also drives **Film Grain**, **Motion Blur**, **White Balance**, **lens character**  (vignette / distortion), **Diffraction Streaks** (sunstars), **Halation** (the red-orange  film halo) and the hybrid **sprite bokeh** highlight splats.Lens values can be pushed live from a phone fader panel by[CryPhoneTracker](../CryPhoneTracker/README.md); the interface is`Interface/ICinematicCameraOptics.h` (`CinematicCamera.dll` exports`CryGetCinematicCameraOptics(IEntity*)`).Schematyc functions: `Activate`, `Deactivate`, `IsActive`.---## Camera slots and switchingEvery cinematic camera can carry a **Camera Slot** number (1-9, `0` = no slot, the default).The console command```ccam_slot 3```activates the cinematic camera whose Camera Slot is 3, and logs the entity it switched to(or a message when no camera carries that slot). Bind the slots to the number keys to cutbetween cameras while the game runs:```bind 1 ccam_slot 1bind 2 ccam_slot 2bind 3 ccam_slot 3```A Phone Tracker with **Follow Active Camera** enabled moves along with each cut, re-anchoringon the new camera. See [docs/ConsoleReference.md](docs/ConsoleReference.md) for the commandreference.The same switch is available to other plugins as the exported C entry points`CryActivateCinematicCameraSlot(int slot)` and `CryGetActiveCinematicCameraEntity()`.## Single authority: who owns the render stateThe **camera manager decides** which camera is active; the component only caches its answer.Once per frame the plugin hook calls the resolver, which walks the registry of live cinematiccameras, finds the one the manager considers active, and ??when the answer changed ??makesthe dethroned component restore every render state it had taken over. Only theresolver-confirmed active component may write DOF, grain, motion blur, white balance,streaks, sprite bokeh, vignette/distortion or exposure; components in a Preview simulation(asset browser preview windows) never write them at all.`Activate()` activates the sibling `CCameraComponent`, which IS the ownership transfer.`Deactivate()` does **not** null the manager's active camera ??the engine always needs someactive view. Its meaning is: strip this component's cinematic effects (full restore sweep)and mark it suspended, so the entity stays a plain view until another camera activates.`IsActive()` reports false while suspended, and `Activate()` clears the suspension.**Activate On Game Start** must stay opt-in: every component receives START_GAME, so withseveral cinematic cameras in a level the last one to get the event would silently steal theview from an explicit Schematyc `Activate` call.## Edit mode policyEffects split by whether they depend on the view:| Effect | Editor (edit mode) | Game / simulation mode || --- | --- | --- || Depth of field, sprite bokeh, motion blur, film grain, white balance, diffraction streaks | not applied | applied || Vignette, distortion (lens character) | live | applied || Exposure | live | applied |In edit mode the viewport renders through the editor fly camera, so pushing this camera'sfocus and blur onto it would produce meaningless imagery. The aspect guide is different from the letterbox: the letterbox is part ofthe picture (a gate mask that is recorded), the aspect guide only outlines the band of thetarget aspect and shades what falls outside it, so a 2.39 composition can be judged inside a16:9 viewport without committing to the crop.**Focus peaking** tints edges that are inside the depth of field. The in-focus band is exactlythis camera's thin-lens depth of field (`ComputeDOFBounds`, the same near/far pair the DOFmodel uses), with a 5% soft falloff on either limit, so a focus pull moves the tinted regionwith the focus - the near and far limits are re-pushed every frame. Edge response is thelargest absolute luminance difference to the four neighbours of the final image, so what istinted is what actually reads as sharp on screen, not a depth threshold.**Guide legend.** While the guides are on, the component prints two small white labels overthe frame (same opacity as the lines): the aspect of the framing guide, just inside the topleft corner of its band, and a framing readout in the bottom left -`50mm  f/2.8  focus 3.20m  Full Frame`. The stop switches to the T-stop(`T2.9`) as soon as the glass transmits less than all of the light, because that is thenumber a lens is actually pulled by. These are aux-text overlays and follow the same killswitch as the guides.**Diagnosing peaking.** `r_LensPeakingDebug 1` paints the in-focus band as a solid tint withthe edge response dropped, so the band itself is visible; `r_LensPeakingDebug 2` paints thescene depth as a grey ramp (black at the camera, white at twice the far limit) with the bandtinted on top. Both need `r_LensPeaking` above 0. If mode 1 shows a band in the right placebut normal peaking shows nothing, the depth is fine and the picture simply has no edgesthere; if mode 2 is flat, the depth read is what is broken.**Recording safety.** Everything runs at the very end of the PostAA composite, after grain andsharpening, so the overlays are clean of both; nothing upstream of them is touched. They aredriven by `r_LensOverlays`, which the component sets to 1 only while editing (or when**Overlays In Game Mode** is on) and to 0 otherwise, and which can be set to 0 by hand as aglobal kill switch. With the overlays off the composite is bit-for-bit the image it producedbefore this feature existed.---## Exposure modesOnly active with `Enable Exposure Control` on. The component default is **Auto + Bias(game)**.### Manual (physical)The standard photographic equation gives EV100, and the tone mapper's `[EV Min, EV Max]`window is collapsed onto a single value ??exposure comes entirely from the lens, which is theonly way the f-number can change brightness:```EV100   = log2(N^2 / (transmission * t)) - log2(ISO / 100) - EVCompensation + NDstopsapplied = NeutralEV + (EV100 - NeutralEV) * ExposureResponse````applied` is clamped to [-6, 24] and written to both EV Min and EV Max. Exposure Response 1restores strict physics; the default 0.6 mimics the S curve a camera's image processing rollsthe extremes off with.### Auto + Bias (game) ??AutoBiasedKeeps the scene's own adaptation window and shifts it by the lens's **relative** stops:```bias           = (EV100 - NeutralEV) * ExposureResponseEV Min/EV Max  = scene value + bias (clamped -6..24); the auto compensation term is untouched```The engine's night is artist-lit and only a few stops darker than its day, so an absolute EVlock blows out night scenes; this mode lets auto exposure keep tracking the scene while thelens still visibly biases it. The base window tracks external (TOD) writes so the shift nevercompounds frame by frame.### Auto Compensation (legacy)Writes only `E3DPARAM_HDR_EYEADAPTATION_PARAMS.z`, the scene-key auto compensation strength.The engine scales that term by how far the scene is from the reference key, so its sign flipsbetween bright and dark scenes and the aperture cannot affect brightness through it. Kept forcompatibility with older setups.---## T-stop: radiometry on T, geometry on f`Transmission` defines the T-stop:```T = f / sqrt(transmission)```**Radiometry (exposure, the grain light term) follows T** ??glass losses darken the imageexactly like a real lens ??while **geometry (DOF, bokeh size and shape, diffraction) stays onthe f-number**. Whenever the lens changes, the console logs the effective T-stop(`[CinematicCamera] f/2.8 at transmission 0.81 -> T3.1`).---## Depth of field and bokeh### Thin lens```CoC limit c = sensorDiagonal(mm) / 1500 / 1000    (metres)near = d*f^2 / (f^2 + N*c*(d-f))far  = d*f^2 / (f^2 - N*c*(d-f))     (denominator <= 0 -> infinity)```### Focus FalloffThe DOF shader has no sharp band; it computes```hlslcoc = saturate(|depth - focusDistance| / (focusRange * 0.5))^2 * blurAmount```so feeding it the physical depth of field width puts *full* blur exactly where the imageshould still be acceptably sharp. The component feeds `dofWidth * FocusFalloff` instead,which puts the physical DOF limits at `1/falloff^2` of maximum blur (11% at the default 3):the depth of field reads as sharp and the falloff beyond it stays smooth.### Blur amount```blurAmount = clamp(focalLength / max(N, 0.7) / 60, 0, 4)    // reference 85mm f/1.4 ~ 60mm```Deliberately not clamped at 1.0: long lenses wide open produce genuinely larger discs, butthe gather kernel is still 49 taps, so watch for sparse/ringy discs at the top end.### Bokeh polygonThe component writes `Dof_User_ApertureBlades`, `Dof_User_FNumber`, `Dof_User_BladeCurvature`and `Dof_User_BladeRotation` every frame. The renderer's kernel crosses from a circle to theblade polygon over an f/1.2 - f/2.8 window, but **only for curved blades**: at Blade Curvature0 the polygon is fully formed at every aperture (and sharpened further, on purpose), and atcurvature 1 the behaviour reduces to the plain f-stop window. The visual strength of thepolygon is exaggerated by `r_DepthOfFieldBokehShapeStrength` (default 2.0), because thephysical radius modulation is far too subtle at high blade counts (8% for an octagon).`r_DepthOfFieldBokehQuality N` (N >= 3) forces an N-sided kernel for diagnostics. See[docs/ConsoleReference.md](docs/ConsoleReference.md).### Sprite bokeh (hybrid highlights)**Use Sprite Bokeh** switches `r_DepthOfFieldMode` to 0, the hybrid path: the full gather blurruns exactly as in mode 1, and a splat layer is added on top for out-of-focus **highlights**only. A pixel splats when its scene HDR luminance exceeds **Highlight Threshold** (soft kneeof +/-50% around it), and each splat deposits energy scaled by **Highlight Splat Gain**. Ascene with no bright highlights therefore looks the same in either mode. The cvar is saved andrestored like the motion blur cvars, so leaving the camera never strands the renderer in amode nobody asked for.### Shape mask and Mask Aperture**Bokeh Shape Texture** is the silhouette (red channel) of a physical mask mounted in front ofthe lens, pushed to the `Dof_User_BokehShapeTex` post param. It only does anything while thehybrid splats are running, and it is rewritten every frame on purpose: the param texture keepsone slot per render command buffer, and a name written once reaches only one of them.Two separate aperture mechanisms - the mask's value field and the blade polygon - combined as a**physical intersection**: the pupil is `mask ??iris` at every f-number, with`k = Mask Aperture / f-number` the iris radius in mask units.- **k > 1** (iris opened wider than the mask): the mask bounds the pupil; the polygon only trims  whatever of the silhouette pokes past it (the outermost corners first). The gather taps are  importance-sampled from the same clipped pupil, so even the soft halo takes the silhouette.- **k < 1** (iris stopped down past the mask): the polygon bounds the pupil and the mask is  sampled at that scale, so the silhouette is clipped corner by corner and rounded off  progressively until the iris sits inside the cut-out's open centre and the plain polygon  remains. The fill style (radial iris look vs mask value field) follows whichever hole is the  smaller one.The pupil is rebuilt on the CPU in quantized iris steps (the same 64x64 mask pixels the gatherkernel samples), and its fill fraction of the splat quad drives the energy gain exactly - athin cut-out deposits as much light as the disc it replaces at any f-number.The mask is an optical element, not just a shape. The thin-lens depth of field and the maximumblur follow the pupil's bounding circle, `max(f-number, Mask Aperture)`(`GetGeometricAperture()`), so a note cut-out at f/2 in front of an f/1.2 iris producesf/2-sized discs; and the light reaching the sensor is `area(iris ??mask) / area(iris)`,integrated from the mask texture for the current f-number, times **Mask Open Area** (tint),through the T-stop transmission term - so the exposure modes and the film grain light termreact to the partly blocked hole exactly like a neutral density loss, continuously. Therenderer still receives the raw iris f-number. The T-stop log line reports the effectivenumbers: `f/1.2 with mask f/2.0 (iris/mask radius 1.67, tint 100%) -> effective transmission0.21, T2.6, CoC from f/2.0`.The renderer compensates a textured splat for how little of its bounding square a mask passes(~0.35 for the engine's own bokeh masks), so a star reads as present as the circle itreplaces. Domain and shape-texture transitions are logged once per change (`[DOF] gatherdomain=...`, `[DOF] shape texture '...' -> resolved ...`).### Field-dependent pupil (cat-eye, coma, astigmatism)A ray reaching the corner of the frame does not look at the lens straight down the axis: itpasses the barrel and the element rims obliquely, so the pupil it sees is **clipped by themechanical opening** - more the further out it is. **Cat-eye** turns that one fact on, and itproduces corner bokeh cut into lens shapes (long axis tangential), darker edges, dimmer edgebokeh, and all of it fading as the iris closes, at once.The pupil's size relative to the barrel is `Maximum Aperture / geometric f-number`, so nothinghere needs a separate aperture link: stop down from Maximum Aperture and the pupil simply stopsreaching the barrel. **Coma** (radial comet tails, proportional to the square of the pupilradius) rides the same plumbing and vanishes the same way; **Astigmatism** splits the radial andtangential foci, so off-axis blur stretches radially on one side of focus and tangentially onthe other, and being a focus shift it is aperture independent.The mechanical light loss is applied **exactly once**, in the tonemap vignette - it belongs toin-focus pixels just as much as to blurred ones. The gather only reshapes its kernel (itsrenormalisation keeps the brightness) and the splat divides the loss back out of its deposit, sosprite and halo agree at the frame edges. Tuning: `r_DepthOfFieldCatEyeBarrel`,`r_DepthOfFieldCatEyeReach`; diagnostic: `r_DepthOfFieldFieldDebug 1` paints the transmission asa grey ramp. One property, `Squeeze Factor` (S), drives three physically distinctconsequences, each on its own path through the renderer.**1. Field of view and the gate mask.** The projected (desqueezed) format is`sensorWidth * S` by `sensorHeight`, so its aspect is `formatAspect = sensorWidth * S / sensorHeight`(36 x 24 mm at S = 2 gives 3.0:1). When that format is wider than the viewport, the format's*width* is what has to fit: the horizontal field of view comes from the widened capture and thevertical field is derived through the viewport aspect, with black bars taking the rest.```hFOV = 2 atan(sensorWidth * S / 2f)vFOV = 2 atan(tan(hFOV / 2) / viewportAspect)      // formatAspect > viewportAspectvFOV = 2 atan(sensorHeight / 2f)                   // otherwise (spherical, or the format fits)```The bars are drawn in the final composite from the `r_LensLetterbox` cvar, which the componentpushes (and restores) exactly like `r_LensDistortion`: `formatAspect` when the mask is needed,0 otherwise. They are hard-edged, as a real gate mask is. At S = 1 nothing changes.**Show Squeezed Frame** swaps the presentation for the raw anamorphic negative: the same bandthe gate mask would keep is stretched vertically to fill the viewport (`r_LensLetterbox` goesnegative), so the whole picture carries the squeeze - circles become tall ovals, faces go thin -not just the bokeh. The camera frustum is identical in both presentations; switching betweenthem changes nothing about what is in frame, only how the band is shown.**2. Oval bokeh.** The pupil image is compressed horizontally by the same factor, so anout-of-focus point spreads into a vertical oval of `height : width = S : 1`. The gather kerneldivides every finished tap's horizontal component by S (both the polygon and the shape-maskkernels go through this), and the sprite bokeh splat narrows its quad the same way, dividingthe energy-conserving deposit by the oval's real area so brightness is unchanged.**3. Horizontal flare.** The cylindrical front element throws one long tinted line across theframe instead of a star. It is a separate effect on its own switch (`Horizontal Flare`), withits own threshold and its own single horizontal march of three widening iterations - eight tapseach, so `8^3` tap distances span the whole frame width. It follows the *opposite* f-numbercurve to the iris diffraction: strongest with the whole element in the light path and gone byf/11.```wideOpenness = clamp((11 - N) / (11 - 2), 0, 1)     // 1 at f/2 and wider, 0 at f/11amount       = HorizontalFlare * wideOpenness```The flare is pushed whenever the camera drives the render state, regardless of`Enable Diffraction Streaks` - one is a property of the iris, the other of the front element.Both ride the `HDR_Streaks_*` post effect params into the bloom target.---## HalationOn film, light from a very bright source does not stop at the emulsion. It passes through,reflects off the film base and re-exposes the emulsion from behind, in a halo far wider thanthe source itself. In a colour negative the red-sensitive layer sits deepest, so what comesback is red-orange, its edge is soft, and it only appears around sources that genuinely**overload** the emulsion - never around a merely bright sky.Halation is a property of the **film stock**, not of the lens. Unlike the diffraction streaksand the anamorphic flare, nothing here is modulated by the f-number: the four properties arepushed to the renderer exactly as authored, every frame, the same way the streak params are.The pass chain lives in `CBloomStage::ExecuteHalation()`, in the **bloom domain** - it runsright after the streaks, reuses the two quarter-resolution HDR scratch targets they leavefree, and blends into `$HDRFinalBloom` with the same bloom-weight compensation, so it costs nopermanent memory and needs no second tone-map hook:1. **Threshold** the half-res HDR scene at `Halation Threshold` with a soft knee of a quarter   of the threshold (the `HDRStreakThreshold` technique).2. **Spread** it wide, horizontally then vertically, through `HDRStreakStretch` with an   isotropic direction, a stride of `2 + 10 * radius` quarter-res texels and a near-flat per   tap decay of 0.90. This is what sets the halo's width: at radius 0.5 the 7 taps per side   reach 49 texels, about 196 full-res pixels on a 1080p frame.3. **Round** the profile with two `CGaussianBlurPass` passes at distribution `3 + 5 * radius`.   That utility's 16 bilinear taps are pinned to +-8 texels whatever the distribution, so it   cannot widen anything - it only smears the discrete tap gaps into a continuous soft edge.4. **Composite** into the bloom target with the stretch shader at a **zero** step (every tap   lands on the same texel, so the normalised sum is a plain tinted sample), tinted by   `Halation Tint` and scaled by `amount * 8 / bloomCompositeWeight`. The x8 gain is there   because an energy-conserving blur spreads a source over thousands of texels: without it the   halo is physically right and visually invisible.These are the `HDR_Halation_*` post effect params; an unmodified renderer does not know them(reads return 0, writes are silently dropped), so the effect needs this renderer/shader set.Master cvar: `r_HDRHalation` (**2 = diagnostic force mode**: amount 1, threshold 0.5, radius0.7, independent of the game-side params).---## SpecificationsThe design documents behind these features, each one the authority on its own semantics:- [HybridDofSpec.md](HybridDofSpec.md) - the gather + splat depth of field and the pupil model.- [SpriteBokehSpec.md](SpriteBokehSpec.md) - highlight selection and the shape mask.- [FieldPupilSpec.md](FieldPupilSpec.md) - the field-dependent pupil: cat-eye, coma and  astigmatism, and the rule that the mechanical light loss is applied exactly once.- [DiffractionStreaksSpec.md](DiffractionStreaksSpec.md) - sunstars.- [AnamorphicSpec.md](AnamorphicSpec.md) - squeeze, gate mask and horizontal flare.- [HalationSpec.md](HalationSpec.md) - the red-orange film halo.- [ViewfinderSpec.md](ViewfinderSpec.md) - frame guides and focus peaking.- [EffectAuthoritySpec.md](EffectAuthoritySpec.md) - who owns the shared render state.---## Build and deploymentBoth plugins hang off the engine's `Code/CryPlugins/CMakeLists.txt`.
